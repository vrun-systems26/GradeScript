How to use this page

The problem, in one picture

Today: one automation idea gets hand-written 3 times (Home Assistant, Node-RED, IFTTT) and the copies can drift apart. With PulseQL: you write it once, and the 3 versions are generated from that one source, so they can't disagree with each other.

Navigating it (30 seconds)

  1. Pick a rule from the "Load example" dropdown, top right.
  2. You start on the "✏️ Write & Test" tab: the rule itself on the left, in plain syntax. The right side runs it live against 7 pretend sensor readings.
  3. Try it: change a number in the rule (like < 20) and watch the right side re-check itself instantly, no save or reload.
  4. Click the "🔄 See it Translated" tab, top of the page, to see that same rule written for 3 real smart-home platforms — the pill buttons at the top switch between them. All three come from the exact same rule, so they can't disagree with each other.

Quick glossary

Home Assistant
The most popular open-source smart-home platform — you write "automations" in YAML that react to sensors and control devices.
Node-RED
A visual automation tool where you wire together little boxes ("nodes") instead of writing a linear script — its saved format is JSON.
IFTTT
"If This Then That" — a mainstream, beginner-friendly automation app most people have heard of, using simple "Applets."
DSL
"Domain-Specific Language" — a small language built for one job only (here: writing automation rules), instead of a general-purpose language like Python.
Rule
One "if this happens, do that" statement — the thing you write in the left box on the "Write & Test" tab.
Compile / transpile
Automatically translating one piece of code into another language without a human rewriting it by hand.
within (honest note)
Sets a time window on the rule (e.g. within 15m) and gets passed to each target's own time-window mechanism. The live tester below evaluates one reading at a time — it doesn't yet simulate a real multi-reading time window itself.
